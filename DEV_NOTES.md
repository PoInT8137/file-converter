# Заметки по разработке

Решения, принятые по ходу работы, и отступления от исходного плана.

## Окружение
- Python 3.12 (на компьютере есть 3.14, но под 3.12 стабильнее колёса pdf2docx, pillow-heif и PyInstaller).
- PyMuPDF зафиксирован на ветке 1.x (1.28.2). Версия 2.0 тянет onnxruntime, pymupdf4llm и другие тяжёлые зависимости, которые программе не нужны. Тесты проходят на обеих версиях.
- pypdf и pytesseract стоят в окружении, но не используются: всё нужное для PDF делает PyMuPDF, Tesseract вызывается напрямую как tesseract.exe.
- customtkinter 6.0.0, API совпадает с 5.x.

## Движки
- FFmpeg: essentials-сборка с gyan.dev (ffmpeg.exe и ffprobe.exe, около 100 МБ каждый). Полная сборка в два раза больше, нужные кодеки (x264, vpx, lame, opus, vorbis, flac, aac) есть и в essentials.
- Pandoc 3.12.1 с GitHub Releases.
- Сами exe движков не хранятся в git (больше 400 МБ). Их скачивает tools/get_engines.py, build.bat вызывает его сам.
- LibreOffice 26.8 найден на компьютере, конвертации через него проверены вживую.
- Tesseract на компьютере не найден. Вызов и формирование команды покрыты тестами, реальное распознавание не проверялось. Пункты OCR в интерфейсе серые с подсказкой.
- LibreOffice запускается с отдельным профилем в %APPDATA%\FileConverter\lo_profile и только один процесс за раз. Исходный файл копируется во временную папку под простым именем, чтобы не зависеть от символов в пути.

## Конвертации
- Реестр хранит для пары форматов список вариантов с разными движками, берётся первый доступный. Например, DOCX в HTML идёт через LibreOffice, а без него через Pandoc.
- Цепочки разрешены только по правилам: через PDF в PNG и JPG (презентации, документы, таблицы в картинки), через DOCX в PDF, ODT и RTF (например, MD в PDF), через HTML в PDF. Так не появляются бессмысленные пути.
- Многостраничный результат (PDF в PNG, презентация в картинки) кладётся в папку с именем файла, страницы названы имя-01.png, имя-02.png. Если страница одна, получается обычный файл.
- PDF в XLSX: если таблиц не найдено, это ошибка с понятным текстом, а не пустой файл.
- OCR не входит в обычную сетку форматов: он живёт в разделе Распознавание и в быстрых действиях. Для PDF без текстового слоя на экране файла показывается подсказка с кнопкой распознавания.
- Галочка «Удалять исходный файл» перемещает файл в корзину, а не удаляет насовсем.
- Добавлены GIF в MP4 и WEBM, видео в M4A и WAV.

## Интерфейс
- Сборка мусора Python выключена автоматически и запускается из главного потока раз в пару секунд. Иначе сборщик иногда срабатывал в потоке конвертации и удалял шрифты Tk оттуда, окно зависало. Шрифты и картинки кэшируются.
- У CTkFrame размер по умолчанию 200 на 200, поэтому пустые контейнеры создаются с размером 1 на 1 (функция holder).
- Плитки, карточки форматов и функций раскладываются адаптивной сеткой: число колонок зависит от ширины, при 1000 пикселях окна плитки идут в 2 колонки.
- Ctrl+K проверяется по коду клавиши, поэтому работает и в русской раскладке.
- Переключатели качества сделаны своими кнопками вместо CTkSegmentedButton: у стандартного виджета на этой версии артефакты на границах.
- Иконка закрытия файла в шапке вместо текстовой кнопки «На главную»: на узком окне текстовая кнопка не помещалась.
- Перетаскивание через tkinterdnd2 работает (проверено, что tkdnd загружается в исходниках и в собранном exe). Реальное перетаскивание мышью из проводника автоматическими тестами не проверить, проверялось только добавление файлов через тот же обработчик.

## Сборка
- Основная сборка onedir. Папка engines копируется рядом с exe, программа ищет движки сначала там.
- Одиночный exe собирается без движков внутри: с ними он распаковывал бы 450 МБ при каждом запуске. Рядом с ним тоже кладётся папка engines. Без неё одиночный exe использует FFmpeg и Pandoc из PATH, если они есть.
- Режим --convert ФАЙЛ ФОРМАТ [--out ПАПКА] позволяет проверить конвертацию в собранном exe без окна.

## Исправления после проверки на баги
- Цикл обновления окна (App.poll) перезапускается всегда, ошибка в одном событии пишется в error.log и не останавливает обновление статусов.
- Задачи можно отменить: крестик у файла в работе отменяет задачу, при закрытии окна с активными задачами программа спрашивает подтверждение. Внешние процессы (ffmpeg, soffice) убиваются вместе с дочерними через taskkill /T, незаконченные файлы удаляются. Рабочие потоки свои и фоновые, закрытое окно больше не живёт невидимо до конца конвертации.
- CSV: кодировка (UTF-8 или cp1251) и разделитель (; , или табуляция) определяются перед передачей в LibreOffice, файл ему отдаётся в UTF-8. При разделителе ; включается русский формат чисел. CSV на выходе с ; и UTF-8 с BOM, как ждёт русский Excel.
- Ctrl+K: у полей ввода Tk есть своя комбинация Ctrl+K (удалить до конца строки), она перехватывается до неё.
- Поля путей и шаблона имени сохраняются при каждом изменении, «Найти заново» сначала сохраняет вписанные пути. Страница настроек перестраивается при каждом открытии.
- Вся работа с PyMuPDF идёт через одну блокировку: библиотека при импорте включает однопоточный режим MuPDF. Обработчик прогресса pdf2docx берёт только записи своего потока.
- История показывается порциями по 20 записей и не перестраивается, если не менялась. «Все конвертации» строятся один раз порциями, поиск только прячет и показывает готовые строки.
- Журнал на экране файла сделан на обычном tk.Text: CTkTextbox каждые 200 мс ставит after() с lambda и не снимает его при удалении, такой вызов потом срабатывал на чужом обработчике клика с ошибкой. Обработчики событий дополнительно пропускают вызовы без события.
- Имена файлов резервируются на время задачи и освобождаются после неё. Чтение статистики идёт под блокировкой.
- «Удалять исходный файл» срабатывает только для конвертаций, инструменты вроде объединения исходники не трогают.
- Тесты интерфейса используют одно окно на все проверки: несколько окон Tk подряд в одном процессе на Windows иногда не могут прочитать tk.tcl.

## Установщик
- Свой установщик на CustomTkinter (installer\setup_app.py) вместо Inno Setup: Inno не повторяет оформление приложения, а скачать его с jrsoftware.org не удалось, соединение обрывалось.
- Один скрипт работает в двух режимах. С payload.zip внутри это установщик, без него деинсталлятор uninstall.exe (около 19 МБ), который кладётся в папку программы.
- Установка для текущего пользователя, без UAC: файлы в %LOCALAPPDATA%\Programs\File Converter, запись удаления в HKCU, ярлыки создаются через WScript.Shell.
- При установке пишется files.txt со списком файлов. Деинсталлятор удаляет только их и пустые папки, чужие файлы в папке не трогает. Себя и папку он удаляет командой cmd уже после закрытия окна.
- Настройки и история в %APPDATA%\FileConverter при удалении остаются, если не отметить галочку.
- Повторный запуск установщика берёт папку из реестра и ставит поверх. Файлы сначала распаковываются во временную папку рядом, на место переносятся только в конце, поэтому отмена или ошибка не портят уже установленную программу. После переноса отмена недоступна.
- Деинсталлятор работает, только если рядом с ним есть FileConverter.exe и files.txt. Ярлыки и запись в реестре удаляются, только если запись указывает на эту же папку.
